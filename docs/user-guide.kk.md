# KNBench пайдаланушы нұсқаулығы

[English](user-guide.md) · Қазақша · [Русский](user-guide.ru.md)

Бұл нұсқаулық толық жүгірудің барлық кезеңін түсіндіреді: орнату, деректер
жиынтығы, тексеру, іске қосу, жалғастыру және есеп. Өрістердің толық
сипаттамасы — [`dataset-format.md`](dataset-format.md), флагтар мен шығу
кодтары — [`configuration.md`](configuration.md), зерттеу дизайны —
[`methodology.md`](methodology.md).

## 1. Алдын ала дайындық

Сізге қажет:

- Python 3.11 немесе одан жаңа нұсқа;
- OpenRouter аккаунты мен API кілті, өйткені мақсатты модельдер мен судья
  OpenRouter арқылы шақырылады;
- `https://openrouter.ai` адресіне желілік қатынас;
- тек синтетикалық сатып алу құжаттары. Нақты құпия, ішкі немесе жеке
  материалды үшінші тарап API-іне анық рұқсатсыз және деректерді өңдеу
  бағалауынсыз жіберуге болмайды.

KNBench зерттеу өлшемін береді. Ол қауіпсіздік рұқсатын, заңдық қорытындыны
немесе жеткізуші рейтингін бермейді.

## 2. Орнату және баптау

Виртуалды орта жасап, тіркелген тәуелділіктерді орнатыңыз:

```bash
python -m venv .venv
source .venv/Scripts/activate        # Windows, Git Bash
# source .venv/bin/activate          # Linux және macOS
pip install -r requirements.txt
```

Әзірлеу үшін `pip install -e ".[dev]"` KNBench-ті сынақ және құрастыру
құралдарымен бірге орнатады; `python -m pytest -q` желісіз сынақ жиынын іске
қосады. `python -m build` wheel файлын жасайды, ал орнатылған пакет `knbench`
командасын береді (`knbench --version`).

Жергілікті конфигурацияны жасаңыз:

```bash
cp .env.example .env
```

`.env` файлын ашып, `OPENROUTER_API_KEY` мәнін қойыңыз. Онда `TARGET_MODELS`,
`JUDGE_MODEL`, `LOG_LEVEL` және `OUTPUT_DIR` мәндерін де орнатуға болады.
`.env` git-ке қосылмайды; оны commit етпеңіз, кілтті есепке көшірмеңіз және
кілт бар логты бөліспеңіз.

## 3. Деректер жиынтығын дайындау

`data/scenarios.json` файлынан бастаңыз — онда төрт нұсқадан тұратын үш
синтетикалық сценарий бар. Сценарий не әр нұсқа үшін бір рет кеңейтілетін
үлгі (template) түрінде, не жеткізуші мен елден басқа барлық жері бірдей
нақты құжаттар түрінде болады. Инварианттылық қамтамасыз етілетіндіктен,
үлгі режимі қолайлы.

Модельге және төрешіге жіберілетін мәтін ағылшын тілінде болуы керек:
толық кеңейтілген `document_text`, `task_prompt`, сондай-ақ әр тәуекелдің
`risk_id`, `category` және `description` өрістері. Тексеруші кеңейтілген
құжаттарды тексереді, сондықтан жеткізуші не ел мәндерінен алынған кириллше
мәтін қабылданбайды. Құжатқа қосылмайтын, тек анонимдеу үшін қолданылатын
атаулар мен бүркеншік аттар кез келген жазуда бола алады. Модель қайталай
алатын әрбір қысқа нысан үшін `vendor_aliases` және `country_aliases` қосыңыз.

## 4. Деректер жиынтығын тексеру

Кредиттерді жұмсамас бұрын желісіз тексерушіні іске қосыңыз:

```bash
python -m knbench.main validate --scenarios data/scenarios.json --strict-pairs
```

Жарамды жиынтық сценарий, нұсқа және тәуекел санын, сондай-ақ бастапқы
байттардың SHA-256 хешін шығарып, `0` кодымен аяқталады. Әрбір мәселе файлы
мен өрісімен бірге хабарланады; біреуі қалса, команда `1` кодымен аяқталады.
`--strict-pairs` салыстырмалылық ескертуін қатеге айналдырады, бенчмарк
жүгіруі үшін дәл осылай болуы керек.

## 5. Жоспарды алдын ала қарау

Не жіберілетінін және қанша шақыру қажет екенін тексеріңіз:

```bash
python -m knbench.main run --models openai/gpt-6.1-sol,google/gemini-4-carbon \
    --scenarios data/scenarios.json --dry-run
```

Жоспар мақсатты модельдерді, сценарий мен нұсқа санын, алынған трипл санын,
судья моделін, анонимдеу режимін және деректер жиынтығының хешін көрсетеді.
Dry run API шақыруларын жасамайды және API кілтін талап етпейді.

## 6. Бенчмаркті іске қосу

```bash
python -m knbench.main run --models openai/gpt-6.1-sol,google/gemini-4-carbon \
    --scenarios data/scenarios.json \
    --output output/raw_results.json \
    --judge-model anthropic/claude-opus-5.5
```

Әдепкі мәндер қолайлы: бес бір мезгілдегі сұраныс, төрт қайталау, 120
секундтық таймаут және судьяның бір дауысы. Провайдер сұраныстарды шектесе,
`--concurrency` мәнін төмендетіңіз. `--judge-votes 3` судьядан үш рет сұрап,
жауаптарды біріктіреді, бірақ құны үш есе артады.

Бірінші мақсатты сұранысқа дейін жүгіру OpenRouter модель каталогын тексереді
және әр мақсатты модельді және судья моделін растайды. Идентификатор қолжетімсіз
болса, команда ешбір мақсатты сұраныс жібермей `1` кодымен аяқталады және
жетіспейтін идентификатор мен каталог күнін көрсетеді. Каталогты оқу мүмкін
болмаса, жүгіру нақты әрекетті қатемен жабылады. `--dry-run` бұл тексеруді
өткізіп жіберіп, желісіз қалады.

Мақсатты жауаптар әрбір он жазбадан кейін және жүгіру соңында `--output`
файлына сақталады. Бағалау кезінде файл әрбір аяқталған бағалаудан кейін қайта
жазылады; үзілген бағалау кезеңі осы бағалауларды сақтайды, ал бағаланбаған
жазбалар жиналған мақсатты жауаптарымен `skipped` күйінде қалады. Сәтсіз
сұраныс `target_failed` ретінде жазылады және жүгіруді тоқтатпайды; кемінде бір
жазба сәтсіз болса, команда `2` кодымен аяқталады.

Екі опция жүгірудің мағынасын өзгертеді:

- `--skip-judge` тек мақсатты модельдердің жауаптарын жинайды. Жазбалар
  `skipped` күйінде қалады; есеп тек қамтуды көрсетіп, метрикалардың жоқтығы
  туралы ескертеді.
- `--no-anonymize` тек жөндеу үшін. Судья жеткізуші мен ел атауларын көреді,
  жүгіру салыстыруға жарамсыз деп белгіленеді және оның нәтижелерін қалыпты
  жүгірумен салыстыруға болмайды.

## 7. Үзілген жүгіруді жалғастыру

Желі ақауы, сұраныс шектеуі немесе `Ctrl+C` салдарынан жүгіру тоқтаса,
нәтижелер файлында барлық аяқталған жазбалар сақталады. Сол командаға
`--resume` қосып жалғастырыңыз:

```bash
python -m knbench.main run --models openai/gpt-6.1-sol,google/gemini-4-carbon \
    --scenarios data/scenarios.json --resume
```

`--resume` күйі `ok` жазбаларды сақтайды, ал қалған барлық жетіспейтін немесе
сәтсіз триплдарды қайта сұрайды; жиналған, бірақ бағаланбаған жауаптар қайта
сұралады. Ол сондай-ақ таңдалған деректер жиынтығының алдыңғы суретке
сәйкестігін тексереді: бар сценарий немесе нұсқаның құжаты, промпті, тәуекелі,
жеткізушісі, елі, бүркеншік аты немесе бақылау белгісі өзгерсе, команда `1`
кодымен тоқтайды. Жаңа сценарийлер мен нұсқалар рұқсат етіледі, ал таңдалмаған
сценарий, нұсқа немесе модель жазбалары алынып тасталады. Жаңа run id беріледі
және `run_config.resumed_from` алдыңғы жүгіруді көрсетеді. Ештеңе күтпейтін
болса, команда API шақырмай `4` кодымен аяқталады; файлда ағымдағы таңдаудан
тыс жазбалар болса, ол сүзілген көрініске қайта жазылады.

POSIX жүйелерінде `SIGTERM` `Ctrl+C` сияқты өңделеді және сол чекпоинтті іске
қосады. Кейбір Windows консоль сессиялары қабылданатын `SIGTERM` жеткізе
алмайды, сондықтан онда `Ctrl+C` қолданыңыз.

## 8. Есепті оқу

```bash
python -m knbench.main report --results output/raw_results.json \
    --output output/report.md
```

Markdown есебі сегіз бөлімнен тұрады: жүгіру тақырыбы, қамту, модельдер
қорытындысы, сценарий мен модель метрикалары, тәуекел балдарының матрицасы,
табылған және жіберілген тәуекелдер, қателер және шектеулер. Тире анықталмаған
мәнді білдіреді — ешқашан нөлді емес. `--format json` орнына
`output/metrics.json` жазады, ал `--strict` кез келген міндетті метрика
анықталмаса, `2` кодымен аяқталады.

`run` командасы нәтиже файлының қасында provenance sidecar жазады
(`output/raw_results.provenance.json`). Онда run id, Python және тәуелділік
нұсқалары, қосымша git revision, деректер жинағының хеші, модель
идентификаторлары және промпт хештері сақталады; промпттар мен модель
жауаптарының өзі сақталмайды. Sidecar жазу сәтсіз болса, ескерту жазылады,
бірақ дайын нәтижелер жарамсыз болып қалмайды.

Қорытындыға сенбес бұрын матрицаны оқыңыз: дельта таңбасыз амплитуда, ал
матрица қай елдің жоғары балл алғанын көрсетеді. Қамтуды да тексеріңіз; бір
сценарий бойынша орташа мән модель деңгейіндегі нәтиже емес.

## 9. Ақауларды жою

| Белгі | Себебі | Әрекет |
|-------|--------|--------|
| `3` коды, "OPENROUTER_API_KEY is not set" | кілт `.env` немесе ортада жоқ | кілтті қосып, қайта жүгіртіңіз |
| бір сұраныстан кейін `3` коды, HTTP 401 немесе 403 | OpenRouter кілтті қабылдамады | кілтті және оның рұқсаттарын тексеріңіз |
| деректер жиынтығының қателерімен `1` коды | тексеру файлды қабылдамады | әрбір көрсетілген өрісті түзетіп, `validate` қайта іске қосыңыз |
| "invalid configuration", "cannot configure logging" немесе "cannot write" көрсетілген `1` коды | жарамсыз орта айнымалысы немесе журнал/шығыс жолы қалта не тек оқуға арналған | параметрді түзетіңіз немесе жазылатын файл жолын таңдаңыз; CLI бір ағылшынша қате хабарламасын шығарады, traceback жоқ |
| жүгіруден кейін `2` коды | кемінде бір жазба сәтсіз | есептің 7-бөлімін оқып, `--resume` арқылы қайталаңыз |
| `report --strict` үшін `2` коды | міндетті метрика `null` | қамтуды, нұсқа санын және `status` мәндерін тексеріңіз |
| `4` коды | `--resume` күткен трипл таппады | істеуге ештеңе жоқ; бар нәтижелерден есеп жасаңыз |
| барлық метрика тире болып шығады | жүгіру `--skip-judge` қолданды немесе ештеңе бағаланбады | `--skip-judge`-сіз қайта жүгіртіңіз |
| сценарий `partial` | кейбір нұсқалар бағаланбаған | жетіспейтін триплдарды `--resume` арқылы қайталаңыз |
| жиі таймаут немесе 429 | провайдер шектеуі | `--concurrency` төмендетіп, `--timeout` арттырыңыз |

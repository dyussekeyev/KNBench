# KNBench

**Контрфактуальный бенчмарк для выявления геополитической предвзятости и слепоты к рискам у больших языковых моделей в контексте национальной безопасности Казахстана.**

[English](README.md) · [Қазақша](README.kk.md) · Русский

## Что такое KNBench

KNBench проверяет, оценивает ли большая языковая модель один и тот же документ закупки по-разному в зависимости от страны происхождения поставщика.

Фреймворк отправляет синтетические документы закупок (RFP) целевым моделям, меняя только два поля — название поставщика и страну, — а затем оценивает ответы ансамблем LLM-судей, которые не знают, какой поставщик оценивается. Поскольку всё остальное в документе совпадает, систематическая разница баллов указывает на зависимость суждения от страны, а не на различия в самом документе.

KNBench — исследовательский инструмент. Он не выдаёт заключений о безопасности, правовых оценок или рейтингов поставщиков.

## Что измеряется

| Метрика | Смысл |
|---------|-------|
| **Risk Blindness Rate** | Доля заложенных рисков, которые модель не обнаружила |
| **Geopolitical Bias Delta** | Разница между максимальным и минимальным `risk_score` по вариантам одного сценария |
| **Decision Flip** | `True`, если одна модель рекомендует `APPROVE` одному поставщику и `REJECT` другому в одном сценарии |

`risk_score` принимает значения от 0 (максимальный риск) до 100 (безопасно) и отражает, насколько полно модель выявила риски, заложенные в документ.

## Как это работает

1. **Загрузка** набора сценариев. Документ описывается один раз как шаблон либо задаётся для каждого варианта в явном режиме.
2. **Развёртывание** сценария в варианты, различающиеся только поставщиком и страной.
3. **Запрос** к целевым моделям через OpenRouter с детерминированной генерацией (`temperature=0.1`, `top_p=0.9`) и ограниченной параллельностью.
4. **Анонимизация** каждого ответа до оценки: названия поставщиков заменяются на `[VENDOR]`, стран — на `[COUNTRY]`, моделей — на `[MODEL]`.
5. **Оценка** анонимизированного ответа по списку заложенных рисков со структурированным результатом.
6. **Отчёт** с метриками в формате Markdown: таблицы по сценариям, матрица `risk_score` и раздел ограничений.

## Быстрый старт

```bash
python -m venv .venv
source .venv/Scripts/activate
python -m pip install -e ".[dev]"
cp .env.example .env
# Перед реальным запуском добавьте OPENROUTER_API_KEY в .env.

python -m knbench.main validate --scenarios data/scenarios.json --strict-pairs
python -m knbench.main run --limit 1
python -m knbench.main report --results output/raw_results.json
```

Консольная команда — `knbench`, поэтому те же действия можно выполнять как
`knbench validate ...`, `knbench run ...` и `knbench report ...`.

Судья по умолчанию — `anthropic/claude-opus-5.5`; целевые модели по умолчанию —
`openai/gpt-6.1-sol` и `google/gemini-4-carbon`. Для других идентификаторов
OpenRouter используйте `--models` или `--judge-model`. `--dry-run` проверяет
план без API-ключа и сетевых вызовов. Начинайте с `--limit 1`, чтобы
контролировать расходы.

Офлайн-тесты используют имитацию HTTP:

```bash
python -m pytest -q
python -m mypy --strict knbench
```

## Языковая политика

- **Всё, что отправляется моделям, — только на английском.** Документы, промпты задач, системные промпты и рубрика судьи никогда не передаются на другом языке: иначе язык теста становится конкурирующим объяснением разницы баллов наряду со страной поставщика.
- **Техническая справочная документация публикуется на английском** в каталоге `docs/`.
- **Общее описание и инструкции для пользователя публикуются на трёх языках**: английском, казахском и русском, с одинаковой структурой.

## Статус проекта

Фреймворк реализован и работает офлайн: загрузчик данных, клиент OpenRouter с предварительной проверкой каталога и повторами, анонимизирующий судья, метрики, отчёт из восьми разделов, CLI и provenance sidecar. В поставляемом наборе три синтетических сценария и двенадцать вариантов.

12 ноября 2026 года live smoke-тест OpenRouter завершился успешно: использовались одна целевая модель (`openai/gpt-6.1-sol`), одна модель-судья (`anthropic/claude-opus-5.5`), один синтетический сценарий и один голос судьи. Идентификаторы моделей по умолчанию закреплены в `.env.example` и проверяются по актуальному каталогу до любого запроса к целевой модели. Результаты описательные и не являются оценкой безопасности или права.

Инструкции пользователя находятся в [`docs/user-guide.md`](docs/user-guide.md); справочники по набору данных, методологии и конфигурации — в `docs/`.

## Ограничения

- Выборки небольшие; результаты описательные, статистическая значимость не заявляется.
- Анонимизация убирает явные идентификаторы, но не косвенные признаки — характерные формулировки или редкие технологии.
- Оценки зависят от формулировки промпта и модели судьи; сравнение корректно только при фиксированных обоих.
- Допускаются только синтетические документы: они передаются стороннему API.
- Реальный запуск моделей расходует кредиты OpenRouter; при разработке используйте `--limit`, `--judge-votes` и `--skip-judge`.
